# Plano de Comunicacao

**Projeto:** InterceptorSystem
**Data:** 21/04/2026
**Versao:** v2
**Responsavel:** Gerencia do projeto

---

## 1. Objetivo

Definir fluxo de comunicacao para garantir alinhamento entre engenharia, produto e stakeholders sem perda de rastreabilidade.

## 2. Publicos-alvo

- Engenharia (backend, frontend, QA, DevOps)
- Produto e patrocinio
- Operacao/atendimento interno
- Parceiros externos de integracao quando aplicavel

## 3. Canais oficiais

- Repositorio (issues, PRs, historico de commits)
- Documentos de planejamento (`.md`)
- Reunioes semanais e checkpoints quinzenais
- Mensageria para incidentes criticos

## 4. Matriz de comunicacao

| Informacao | Publico | Frequencia | Canal | Dono |
| --- | --- | --- | --- | --- |
| Status de entrega | Time tecnico + produto | Semanal | checkpoint + resumo | PM/Lider tecnico |
| Mudanca de escopo | Stakeholders impactados | Sob demanda | issue + plano atualizado | PM |
| Risco critico/incidente | Time tecnico + patrocinio | Imediato | alerta + registro formal | Responsavel do risco |
| Fechamento de marco | Todos os envolvidos | Por marco | nota de versao/documento | Dono da entrega |

## 5. Regras

- Decisoes relevantes precisam de registro rastreavel
- Nao usar canal informal como fonte unica de decisao
- Mudanca aprovada deve gerar comunicacao explicita de impacto
